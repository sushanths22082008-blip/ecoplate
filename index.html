Forecast model report

The model (scikit-learn Gradient Boosting) learns from your saved meal records. It is retrained automatically whenever the records change. Before it is allowed to produce forecasts it is tested on your most recent days, which it has not seen during training, and compared with simple baselines. Bulk import of historical records

Add months or years of past records at once instead of typing them one by one.

  1. Download the CSV template and copy your records into it. Columns: Date, Meal, Prepared, Leftovers.
  2. Using Excel? Choose File → Save As → CSV UTF-8 (Comma delimited).
  3. Choose the file below. Nothing is saved yet. You will see a preview first.
  4. Check the preview, then click Confirm import.
PDF reports and handwritten registers cannot be read directly. First convert or type them into a spreadsheet, check every row by eye, then save as CSV.
Rules for each row
  • Date: YYYY-MM-DD (for example 2026-03-05) or DD-MM-YYYY / DD/MM/YYYY (day first). Must be a real date, not in the future.
  • Meal: Breakfast, Lunch or Dinner (capital letters do not matter).
  • Prepared: whole number, at least 1. Leftovers: whole number, 0 or more, not more than Prepared.
  • Optional fifth column Synthetic: write yes on rows that are invented sample data, so the model can warn that its accuracy scores are not real-world results. The built-in sample file uses it.
  • One row per date and meal. Duplicates (already saved, or repeated in the file) are skipped. Saved records are never overwritten.
  • Limits: 10 MB and 50,000 rows per file. Split bigger files.
Moving records from the old EcoPlate page (before the server version)?

The old page kept its records inside your browser, under the address file://…. This server version lives at http://127.0.0.1:5000, which is a different address, so a browser never shares data between the two. Easiest transfer: open the old page, go to Backup & Reset → Full backup (JSON), then come back here and use Backup & Reset → Merge an old backup. A CSV export from the old page also works with the file chooser below. Nothing is overwritten.

About this prototype

  • Real machine learning, with safeguards: forecasts come from a scikit-learn Gradient Boosting model trained on your own records, but only when there is enough history and the model beats simple baselines on a held-out recent period. Otherwise a rule-based average is used and labelled as such (see the Model tab).
  • Where data lives: meal records are stored by the local EcoPlate server in a SQLite file (ecoplate.db). The surplus register is still stored in this browser (localStorage). Full backups include both. This is a single-computer prototype with no user accounts; a real canteen system needs proper access control.
  • Sample data is not real: accuracy scores measured on sample (synthetic) records only describe that invented data, not a real canteen.
  • Always check imported data. The forecast is only as good as the records.
